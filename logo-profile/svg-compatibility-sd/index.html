Backend: SDWebImageSVGCoder 1.8.0 through our PNG adapter. This is compared with the earlier fixed-sRGB CoreSVG probe, not a second SDWebImageSVGCoder instance. Upstream uses the macOS display color space and rounds its aspect-fit bitmap dimensions; colors and edge placement may differ. Pixel review failures remain visible and do not imply a parse failure. The alpha-channel sample has identical native-AA alpha at 256px despite RGB differences.

SVG compatibility: SwiftSVGWebImage vs CoreSVG

Three demo inputs from SDWebImageSVGCoder, plus seven stress samples from the SVGWeb collection its demos use. This is a bounded comparison, not full SVG conformance certification.

Reference: the same CoreSVG create/canvas/draw entry points used by SDWebImageSVGCoder, invoked in a standalone development tool. Both outputs use centered aspect fit in square sRGB canvases; the actual coder changes bitmap canvas dimensions to fit. No private API is added to the library.

Sizes: 64, 256, 1024 pixels. Native antialiasing and default Lanczos. Each successful render is warmed once then timed three times, including upstream parsing and PNG encoding, excluding network/cache; parse-only timing is unavailable and shown as 0. CoreSVG timing is not compared. Images below are 256px, native antialiasing. Error is measured after compositing on both black and white, taking the worse result. Review threshold: mean channel error ≤1/255 and ≤1% pixels differing by more than 16/255 in any channel. This is a heuristic, not proof of correctness. Pixel differences are not a semantic verdict; inspect the image.
